What the footage is, and why it matters

Two pages that link this video ID list it as “ITN theme song – Samanola Siripa Piyuma Dowagena”, uploaded by Muditha Liyanagama. A Sinhala-music forum thread calls it the theme ITN's Sinhala service used to air. ITN started broadcasting in 1979, so this is almost certainly analog PAL-era live-action TV, not animation. Check the title on YouTube matches before you start.

  • Live action, so use the Real-ESRGAN general models. Skip the anime-tuned options in the same tools (Real-CUGAN, Anime4K, realesr-animevideov3, waifu2x). Users restoring VHS footage report those make real faces look “too cartoony”.
  • Probably 4:3. Upscale to 1440×1080 and let the player add the side bars. Stretching it to 1920 wide distorts every face.
  • Possibly interlaced. Analog TV was recorded as alternating half-frames. If you see comb-like lines on moving edges, deinterlace before upscaling. An upscaler will sharpen the combing into the picture.
  • YouTube's 480p is a re-compressed copy. The upload was named as an .mkv file, so the uploader likely still has a cleaner original. Asking for it gives a better result than any setting.
  • Length not confirmed. Set it in the cost chart below to get time and cost estimates.

The pipeline

Only the video goes through processing. The audio goes around it in a separate lane and is copied into the final file unchanged, so it stays exactly as it is now.

Steps

The commands use the free tools: ffmpeg and Video2X. On Windows, run them in PowerShell from the folder that holds your file. On Colab, the notebook has its own cells for steps 4 and 5.

  1. Get the best copy you can

    First ask the uploader for their original file. Their YouTube upload was named as an .mkv, and that original will have less compression damage than YouTube's 480p stream. If you can't get it, use the highest-quality stream YouTube offers, and read the rights note below first. Name the file source.mkv.

  2. Inspect it

    Read four things from the output. width×height and display_aspect_ratio give the shape: 640×480 or 4:3 means a 1440×1080 target, and 854×480 means 1920×1080. field_order should say progressive; tt or bb means interlaced. r_frame_rate should be 25 for PAL.

    ffprobe -v error -select_streams v:0 -show_entries stream=width,height,display_aspect_ratio,sample_aspect_ratio,field_order,r_frame_rate -of default=nw=1 source.mkv

  3. Cut a 10-second test clip

    Pick a stretch with a face and some movement. Change the start time to suit.

    ffmpeg -ss 00:00:30 -i source.mkv -t 10 -c copy test.mkv

  4. Run both general models on the test clip

    realesr-general-x4v3 removes more grain. realesr-general-wdn-x4v3 denoises less and keeps more texture. Compare them full-screen and pick the one where faces look like skin, not plastic. In the Video2X GUI, choose processor Real-ESRGAN, the model, and scale 4.

    Stronger denoise 
    video2x -i test.mkv -o test-x4v3.mkv -p realesrgan -s 4 --realesrgan-model realesr-general-x4v3 -c libx264rgb -e crf=12 -e preset=slow
    Lighter denoise, more texture 
    video2x -i test.mkv -o test-wdn.mkv -p realesrgan -s 4 --realesrgan-model realesr-general-wdn-x4v3 -c libx264rgb -e crf=12 -e preset=slow

    Set the encoder yourself as shown. Don't rely on Video2X's defaults. CRF 12 is a near-lossless intermediate, so quality is only spent once, in step 6.

  5. Upscale the whole video with the winner

    Same command, with the full file as input. The output is about 2560×1920. It gets scaled down to 1080 lines in the next step, which also tightens the detail.

    video2x -i source.mkv -o upscaled-4x.mkv -p realesrgan -s 4 --realesrgan-model realesr-general-wdn-x4v3 -c libx264rgb -e crf=12 -e preset=slow

  6. Scale to 1080, encode, and copy the original audio in

    One command does three things. It takes the picture from the upscaled file and scales it to 1080 lines high, keeping its shape. It encodes that picture once, at high quality. And it copies the audio from source.mkv without decoding it. MKV holds YouTube's Opus or AAC audio as-is.

    ffmpeg -i upscaled-4x.mkv -i source.mkv -map 0:v:0 -map 1:a:0 -vf "scale=-2:1080:flags=lanczos" -c:v libx264 -preset slow -crf 17 -pix_fmt yuv420p -c:a copy final-1080p.mkv

    CRF 17 looks almost identical to the input. If you upload the file, YouTube re-encodes it anyway. Its guidance for 1080p at 24–30 fps is about 8 Mbps.

  7. Compare before you call it done

    Play the source and the result side by side on the largest screen you have, at the same moments. Check faces, the station logo and any text, and fine patterns such as fabric. If something looks off, use the fixes below and rerun from step 4 on the test clip.

If the test looks wrong

Faces look waxy or plastic
Switch to realesr-general-wdn-x4v3. For finer control, the Real-ESRGAN Python script sets denoise strength from 0 to 1 with -dn. One VHS restorer used 0.3, and the default is 0.5. In Topaz, lower Iris or turn it off, and keep Proteus denoise around 10–20.
Grain is still visible
Use realesr-general-x4v3. If that isn't enough, add a light denoise before upscaling: ffmpeg -i source.mkv -vf "hqdn3d=2:1.5:4:3" -c:v ffv1 -c:a copy clean.mkv, then upscale clean.mkv. Topaz advises denoising before upscaling. Real-ESRGAN users report it makes little difference, because the model already denoises. Test both.
Comb-like lines on moving edges
The source is interlaced. Add bwdif=0, at the front of the filter in the pre-clean command (-vf "bwdif=0,hqdn3d=2:1.5:4:3"), or use -vf bwdif=0 alone.
Bright halos around edges
Don't add sharpening. Denoising and upscaling already add apparent detail, and Topaz's own guidance warns against stacking a sharpen pass on top.
People look wide and squat
The 4:3 picture was stretched to 16:9. Keep scale=-2:1080 as written: it sets the height and works out the width from the picture's shape.
Colab fails with vkQueueSubmit failed
One user reported this on a T4 in Aug 2026 (issue 1509, not yet confirmed by others). Try a smaller tile size, or switch to RunPod.

!Rights and downloading

  • YouTube's Terms of Service don't allow downloading except through YouTube's own features or with permission from YouTube and the rights holders. Third-party downloaders such as yt-dlp work technically, but using one on this video breaks those terms. In Germany, a court in 2024 held that youtube-dl gets around YouTube's technical protection.
  • The footage and song most likely belong to ITN and the song's creators, not to the uploader.
  • If you re-upload the improved version, Content ID will usually still match it. That can mean a claim, a block or a strike, and YouTube won't monetize an upscaled copy as original content.
  • The clean path is to get the original file from the uploader or an archive copy from ITN. Keep the result for personal viewing unless you have permission to share it.
